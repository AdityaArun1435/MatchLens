# Phase 2 plan: grounded recaps and explanations

## Rule
The LLM sees only the `MatchSummary` and `Moment` list of one match, rendered as compact text (`recap/context.py`).
No raw events. Every paragraph cites moment ids and the backend checks the output before anything reaches a user.

## Layout
```
matchlens/llm/        provider.py (Protocol + errors), ollama.py, fake.py, factory.py
matchlens/recap/      models.py (Recap, MomentExplanation, report, request params)
                      context.py (summary + moments -> compact text, one function decides what the model may see)
                      validate.py (citations, numbers, names; pure functions)
                      pipeline.py (generate -> validate -> retry once -> drop -> fallback; explanations the same)
                      fallback.py (deterministic recap/explanation, no LLM)
                      cache.py (data/generated/, key includes model + prompt-file hash)
matchlens/api.py      POST /matches/{id}/recap, GET /matches/{id}/moments/{moment_id}/explain
prompts/              system, audience_*, length_*, language_en, recap_task, explain_task, retry (plain files)
scripts/generate_recap.py
```

## Decisions
* **Provider**: `LLMProvider.generate_json(system, user, json_schema) -> dict`. Ollama via `/api/chat`, `format` = JSON
  schema, `think: false`, temperature 0.2, fixed seed, `num_ctx` 8192 (fits 8 GB VRAM with an 8B Q4 model). The schema is built per
  request with the shown moment ids as an `enum`, so the model cannot even emit an unknown id; the validator still checks.
* **Numbers check** compares against the numbers in the exact text the model was shown (summary + cited moments), so
  "allowed" cannot drift from the prompt. Scores (`2-2`), stoppage minutes (`90+3'`), decimals and integers are separate token
  kinds. Number words next to a counted noun ("two goals") and "twice" are checked as well.
* **Names check**: roster match (full name, display name, surname, given name) against names visible in the cited moments,
  plus a capitalised-word pass for names that are not on the roster at all.
* **Retry once** with the exact errors, keep the attempt with more valid paragraphs, drop the invalid ones, else template fallback.
  A provider that is not running is an error, not a fallback.
* **Cache** only LLM-produced results, never fallbacks. Filenames avoid `:` (model names like `qwen3:8b`) for Windows.
* `language` is a real parameter everywhere (`en` only today); prompts load `prompts/language_<code>.md`.

## Steps (one commit each)
1. Config + providers + provider tests
2. Models, prompts, context builder
3. Validators + tests
4. Pipeline, fallback, cache + tests
5. API + CLI + tests
6. README, integration test (`needs_ollama`), PR

## Not verifiable in this session
The session ran in a cloud sandbox with no GPU, no Ollama and `ollama.com` blocked, so real-model recaps are generated by
`python scripts/generate_recap.py --match <id> --audience all` on the laptop. Everything else is tested with `FakeProvider`
and an `httpx` mock transport for the Ollama client.
